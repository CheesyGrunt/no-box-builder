Stage 2  ·  Steps 4 and 5

Client ID batches

7 bundles or fewer. Never more than 70 IDs each.

70 is the most Client IDs Salesforce will take in one filter, and 7 bundles is the most this process runs. The size box holds you inside both limits, so you cannot land on 13 bundles of 35 by accident.

If a month is big enough that it will not fit into 7 bundles even at 70 each, stop and reach out to the Director of Virtual Services or the Salesforce Administrator.

And do not save over this report. Update the filter, click Run, export. Never click Save. Saving rewrites the shared report for everyone who uses it.

Mess up the report and you will be banished to Azkaban.

Copy each bundle into the Part 2 report filter, one bundle at a time. Filter logic stays the same: Program Engagement Name AND (Client IDs) AND Created Date AND Service Delivery Name

Stage 5  ·  The handoff

Publish it for staff

This encrypts the finished list with the team password and downloads one file. Put that file in the repo and staff can open the site and read it. They never touch an export and never upload anything.

How the encryption works

The password is the key. What gets committed is ciphertext, so even if the link gets out, the file is unreadable without the password. It is decrypted in the reader's browser, never on a server.

Getting your access token, one time only
Five clicks in GitHub

Profile photo → Settings → scroll to Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.

Name it "No Box publisher". Set an expiration you will remember, a year is reasonable. Under Repository access pick Only select repositories and choose this one repo. Under Permissions → Repository permissions, set Contents to Read and write. Leave everything else alone. Generate, then copy the token and paste it above.

The token only reaches GitHub. It is never written into the repo. If you tick Remember, it stays in this browser on this computer, so treat that the way you would a saved password. If you lose the laptop, revoke the token in the same GitHub screen.
