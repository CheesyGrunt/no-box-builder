One-time setup

Sealing the Vault

This page runs once. It locks your GitHub key inside a file that only your passphrase can open.

Everything happens in this browser. Nothing is sent anywhere. You end up with one small file to place in your repository.

Choose a passphrase

Six characters minimum. Longer is stronger, but short is fine on a private repository.

There is no reset. If you lose this, run setup again and replace the file.

Where the site lives

The key itself

Scope it to this one repository with Contents set to read and write. Nothing else.

Minting the token

  1. Go to github.com/settings/personal-access-tokens/new
  2. Name it vs-dashboard-publish and set an expiry you will remember
  3. Repository access: Only select repositories, then pick this one repo
  4. Permissions: expand Repository permissions, set Contents to Read and write. Leave every other permission alone.
  5. Generate, copy the token, and paste it above

Read this part

Make the repository private in its GitHub settings. Render deploys private repositories on the free tier just the same, and your live site stays public either way. It takes about thirty seconds and it is the single thing that matters most here.

Here is why. The sealed file lives in the repository. On a private repository nobody can download it, so a short passphrase is perfectly fine. On a public one anyone can grab it and take unlimited guesses on their own machine, and a six character passphrase does not survive that. Short passphrase and private repository is a good combination. Short passphrase and public repository is not.
